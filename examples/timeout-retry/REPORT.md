# 首轮交接测试

## 执行方式

2026-09-20，当前对话Agent读取xiaobai/SKILL.md及合并角色图，消费[固定版本8页分镜](https://github.com/SlamWeb/knowledge-to-storyboard/blob/9abf556ef4d231710c8a83db8a5d45bfad8c16c3/examples/timeout-retry/storyboard.md)，产出[prompts.md](prompts.md)。未调用另一个独立模型，不是盲测；未生图，不消耗图片额度，不修改CreatorOS或正式数据。

## 已验证

- 原8页输出8个独立Prompt，页序和cover/content/synthesis角色一致。
- 自动比对25段上屏文字（8标题、8正文、8标签组、1思考题），全部原样保留；未将研究备注印入图片。
- 每页都有可解析的同一张角色图引用；实际查看角色图后加入灰色尾部等形象约束。真正生图时仍须附上图片。
- 人工对照：第2页保留互斥可能路径；第4页保留范围/有效期；第5页将跨系统扣款留在本地事务外；第6页保留Stripe特例和“已保存”；第7页停止重试不等于业务失败。
- 封面为视觉悬念，正文知识图主导，总结为整体判断路径；角色比例随页面角色变化，不将每页写成海报。

## 发现与局限

1. 输入契约有两个方言：本次原版为认知目标/上屏定稿/关系说明，深度版为核心问题/机制/Aha/Visual Semantics。此次按语义映射成功，不说明深度版已跑通。接入时识别两种形式，别为了凑字段伪造内容；缺少实际机制或关系时退回上游。
2. 第5页仍有较高密度。文字完整性通过不证明9:16图片可读；后续应渲染此页检查，排不下需上游修订，不允许视觉阶段静默删改。
3. 每页Prompt独立重复系列约束，便于逐页调用但有Token开销；这是明确独立交付的取舍，暂不增加模板执行器。
4. 当前输出是Prompt，不是图片。跨页角色稳定、中文准确、字号及图形逻辑还没有视觉验收，不报告虚构成功率。

## 对后续接入的建议（尚未实施）

- 栏目配置将“内容方法”和“视觉形象”作为两项选择，名称、用途、预览清楚，不直接暴露安装路径等内部字段。
- 每次生产保留所用两项Skill及资产版本；修改栏目默认值不静默改写旧任务。
- 保存可查看的storyboard与逐页Prompt，再生成图片；这可以仍由一次Codex生产任务完成，不强制新增两个Agent或两次审批。
- 前端围绕选题→内容→图片→验收组织。中间文档可展开检查，默认不把PageSpec字段逐项铺在运营页面上。
- 先定内容是否要人工确认再生图、如何只换风格重做，再改双Skill接线和页面；旧单Skill任务需要保持可读与兼容。
